## Description

`get_next_line(int fd)` は、ファイルディスクリプタから1行ずつ読み取る関数です。
改行があれば改行を含めて返し、末尾に改行がなければ最後の文字まで返します。
EOFで返す文字がない場合、またはエラーが起きた場合は `NULL` を返します。
通常のファイルと標準入力に対応する必須部分を実装しています。

複数のファイルディスクリプタを交互に読むボーナス部分は実装していません。

## Instructions

利用するプログラムから `get_next_line.h` をインクルードし、次のようにコンパイルします。
`main.c` は利用側で用意してください。

```sh
cc -Wall -Wextra -Werror -D BUFFER_SIZE=42 main.c get_next_line.c get_next_line_utils.c -o gnl
```

`-D BUFFER_SIZE=42` を省略した場合も、既定値は42です。
ソースだけをコンパイルする場合は次のコマンドを使えます。

```sh
cc -Wall -Wextra -Werror -c get_next_line.c get_next_line_utils.c
```

`get_next_line(fd)` を `NULL` が返るまで呼び出し、返された行は使用後に
呼び出し側で `free()` してください。標準入力には `fd = 0` を指定します。
同じ入力はEOFまで読み切ってから、次の入力へ切り替えてください。
読み取り途中には、次回用のデータが内部に保持されます。
`BUFFER_SIZE` が0以下の場合は `NULL` を返します。

## Algorithm

1. `static t_stash stash` に、保存領域のポインタ、データの長さ、
   確保済み容量、改行を検索する位置を保持します。
2. 未確認の位置から改行を探します。改行がなければ保存領域の末尾へ
   `BUFFER_SIZE` バイトまで直接読み足し、その続きから検索します。
3. 容量が足りないときだけ、必要量と現在の容量の2倍のうち大きい方を確保し、
   既存データを移します。容量計算では整数のオーバーフローも確認します。
4. 改行まで（EOFの場合は残り全部）を別の領域にコピーし、終端文字を付けて返します。
   未返却の部分は保存領域の先頭へ移動し、検索位置を0に戻します。
5. 残りが空になった場合や、読み取り・メモリ確保に失敗した場合は、
   保存領域を解放し、構造体の各フィールドを初期状態に戻します。

保存領域は長さで管理し、返却する行にだけ終端文字を付けます。
外部関数は `read`、`malloc`、`free` のみです。
補助処理は、[get_next_line_utils.c](get_next_line_utils.c#L15) の5つの関数に分けています。

| 関数 | 役割 |
|---|---|
| `gnl_clear` | 保存領域を解放し、ポインタと管理情報を初期化する |
| `gnl_copy` | 指定したバイト数を先頭からコピーする。前方への重なりのある移動にも使う |
| `gnl_reserve` | 容量が不足したときだけ、領域を拡張して既存データを移す |
| `gnl_read` | 検索位置を進めながら、改行またはEOFまで読み足す |
| `gnl_take` | 最初の1行を取り出し、余りを保存領域の先頭へ移動する |

行の長さをL、バッファサイズをBとします。
容量を原則2倍ずつ拡張するため、拡張時のコピー量の合計は長さに比例します。
改行検索も確認済みの部分を再走査しません。
長い1行を読み取る際のコピー・検索の合計は、読み越し分も含めO(L + B)です。
ただし、1回の拡張では既存データ全体をコピーします。また、行を返すたびに
余りを移動するため、大きなバッファ内の多数の短い行では、その移動の負担が残ります。

使用メモリはO(L + B)です。保存領域の容量は余りがある間は縮小しないため、
このメモリ上限のLは、それまでに扱った最長行の長さを表します。
呼び出し側が返却された行を保存し続ける場合、その分は別途必要です。

## Structure

[get_next_line.h](get_next_line.h) の `t_stash` は、まだ返していないデータと、
その保存領域を管理する情報をまとめた構造体です。

```c
typedef struct s_stash
{
	char	*data;
	size_t	length;
	size_t	capacity;
	size_t	scan;
}	t_stash;
```

| メンバー | 役割 |
|---|---|
| `data` | 読み取って、まだ返していないデータの保存領域へのポインタ |
| `length` | 保存されている有効なデータのバイト数 |
| `capacity` | `data` に確保してある領域のバイト数 |
| `scan` | 次に改行を調べる位置。改行が見つかった場合は、その位置 |

`length` は使用量、`capacity` は確保済み容量です。この2つを分けることで、
空き容量が十分なら再確保せず、`data + length` の位置へ直接読み足せます。
内部データは `length` で管理するため、終端文字を探して長さを数える必要はありません。

`scan` は、改行を確認済みの部分を再走査しないために保持します。
例えば `abc` を調べ終えた状態では `length = 3`、`scan = 3` です。
続けて `de\n` を読み足すと `length = 6` になり、位置3の `d` から検索を再開します。

保存データが `abc\nde` の場合、改行を見つけてから行を返すまでの状態は次のようになります。
容量は説明用に8バイトとしています。

| 状態 | 有効なデータ | `length` | `capacity` | `scan` |
|---|---|---:|---:|---:|
| 改行を発見 | `abc\nde` | 6 | 8 | 3 |
| `abc\n` を返却 | `de` | 2 | 8 | 0 |

返却後は余りの `de` を先頭へ移し、検索位置を0に戻します。
領域は縮小しないため、`capacity` は変わりません。
`length` より後ろに古いデータが残っていても、処理対象にはしません。

`get_next_line()` では `static t_stash stash` と宣言し、呼び出しをまたいで
状態を保持します。初回は `data` が `NULL`、他のメンバーが0に自動初期化されます。
残りが空になった場合やエラー時には、`gnl_clear()` が領域を解放し、同じ初期状態へ戻します。

補助関数には `&stash` を渡すため、`stash->length` のように `->` を使って
呼び出し元の構造体を直接更新できます。
`s_stash` は構造体のタグ名、`t_stash` は `typedef` で付けた型名で、
どちらもNormの命名規則に従っています。
